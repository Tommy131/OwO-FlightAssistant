## v1.2.0-beta — 2026-08-26

### 新增

- **自动落地报告**：MSFS 2020/2024、X-Plane 11/12 进入终端进近后使用与手动飞行日志分离的采样器，落地稳定后自动生成报告；设置页可关闭，默认开启。
- **落地报告工作区**：飞行日志页新增独立内联子页，可在列表与详情间往返，查看接地、拉平、进近稳定性、气象、构型和逐样本证据。
- **中断录制恢复**：手动飞行日志和自动落地报告在模拟器断开、人工停止或网页关闭时立即持久化，并保留「未完成」状态和具体结束原因。

### 调整

- **落地高度数据语义**：记录真实无线电高度与几何 AGL 回退的来源，落地报告按模拟器能力选择可用高度，不再把两者混为同一个值。
- **落地报告持久化**：前后端使用修订号、墓碑和冲突合并保护跨页面及多客户端同步，旧版本数据仍可读取。

### 删除

- 无。

### 修复

- **MSFS SimConnect 数据映射**：修正 MSFS 2020/2024 的字段布局、单位与系统事件解析，修复灯具指示、G 值、暂停状态及其他遥测映射偏差。
- **MSFS 落地无线电高度**：优先使用真实 `RADIO HEIGHT`，不可用时明确回退到 AGL，避免落地报告高度缺失或严重失真。
- **地图底图密钥水印**：用无需向浏览器下发 API Key 的 Esri 深色/浅色画布及独立注记层替代 CARTO，消除「API KEY REQUIRED」背景。
- **MSFS 进近 PAPI**：未手动选择机场时自动加载最近机场跑道；旧的手动机场不匹配当前进近时会回退到最近机场，PAPI 不再无故消失。
- **录制完整性**：修复崩溃窗口、延迟水合、重复恢复和保存失败时的竞态，避免中断记录丢失、被重复恢复或被错误标记完成。

## v1.0.10-beta — 2026-08-11

### 新增

- **自动更新检测（模块 `modules/update/`）**：启动后台查一次发行仓库，有新版本
  就用 SweetAlert2 弹窗显示更新日志，可选「立刻更新 / 忽略此版本 / 稍后再说」。
  设置页新增「软件更新」，显示当前状态（有可用更新 / 已是最新 / **该版本已被忽略** /
  检查失败），并可手动检查（强制回源，不吃缓存）、取消忽略、查看发行页。
  「立刻更新」由中间件下载并替换自身，界面上跟进度直到重启。
  发行说明的渲染是**自己写的 Markdown 子集**（先转义再包标签），没有接通用
  Markdown 库 —— release body 是外部文本，通用渲染器会把 `<script>`、
  `<img onerror>` 原样吐出来。覆盖标题、有序/无序列表（含缩进续行）、引用块、
  分隔线、段落，行内支持代码、粗体、斜体、删除线与链接。
  刻意不支持三样：下划线强调（本项目 snake_case 标识符满地，会被拆成斜体）、
  图片语法（弹窗一打开就会对任意 URL 发请求）、非 http(s) 协议的链接（降级成纯文字）。
  判定与渲染在 `services/update-model.ts`（纯函数、57 条单测，其中一批是注入用例）。

- **地形告警（TODO H）**：地图上按「相对本机高度」给地形分级着色
  （高于本机 / 本机 1000 ft 内 / 低于本机 1000–2000 ft，更低的不画），
  并沿当前航迹前视扫描地形，60 s 内余度不足报「注意前方地形」、
  30 s 内报「前方地形，立即拉起」。高程走中间件的在线 DEM 瓦片接口，
  与模拟器无关，X-Plane 与 MSFS 2020/2024 通用。
  判定与着色在 `services/terrain-model.ts`（纯函数、34 条单测）。
- **当地时间 / UTC（TODO K）**：机场详情卡显示该机场当地时间与 UTC，
  跨日时把日期一并标出；飞行中左下角的航空器迷你卡新增 `LT` 一格，
  显示本机所处位置的当地时间。时区查一次拿 IANA 名，之后本地用 `Intl`
  每秒自己走时，夏令时自动正确。格式化在 `services/local-clock.ts`（纯函数、20 条单测）。

### 调整

- 告警可配置清单改为从 `ALERT_MESSAGE_KEY` 一张总表派生（后端告警 + 前端自判的地形告警），
  设置页与地图弹出的告警共用同一份文案，不会再露出裸 id。
- 地形图例文案从「危险/警告/注意」改为说明分级含义的「高于本机 / 本机 1000 ft 内 /
  低于本机 1000–2000 ft」。
- **溢出跑马灯提升为通用组件**：原本只服务地图机场卡的 `MarqueeText` 移到
  `core/widgets/common/`，铺开到侧边栏导航项与分组标题、顶栏页面标题、
  卡片标题与副标题、信息胶囊、弹出菜单项、移动端底栏标签。
  仍是「先量宽、放不下才滚」，放得下的短标签不会动；截断样式从各处样式表
  收归组件自身。悬停暂停以便看清全文。

### 删除

- 无

### 修复

- 地形告警上报接口从来没被调用过：筛选条件写的是 `alert.id === 'terrain_warning'`，
  而那是开关 id，真正的告警 id 是 `terrain_pull_up_*`。改为按 `terrain_` 前缀筛。

- **跨模块跳转跳到了别的页面**：`goToIndex`、恢复上次页面、消费
  `NavigationCommandBus.goTo` 三处都用 `getAllItems()` 把 id 换算成下标，
  而它是「所有项按各自 priority 整体排序」，不认分组；真正渲染、也就是
  `selectedIndex` 所索引的，是「先按组、组内再按 priority」的那份。
  11 个导航项里 10 个都分了组，两份顺序整体错位 —— 顶栏任务流菜单点哪一步
  基本都跳错页。三处统一改用同一份顺序。

- **任务流菜单点了像没反应**：菜单按「任务流阶段状态」标选中，那表示的是
  「下一步该做什么」而不是「你在哪一页」，点进去标记纹丝不动。
  下一步已由标签前的 ▸ 表示，选中态改为跟随当前页（导航层新增常驻 `currentId`）。

- **「跳过当前步骤」点下去计数不动**：`acknowledge` 只改了内部集合，派生状态
  等着外部 store 调 `recompute` 才更新；没连模拟器时那几个 store 根本不动，
  于是箭头和 0/4 一直停在原地。改为立刻按留存的外部输入重算，并补了回归单测。

- **设置页露出裸占位符**：「当前地址: {address}」「当前默认机场: {value}」
  两处文案声明了命名占位符，调用方却没传参（值是在 `t()` 之外自己拼的），
  未匹配的占位符按设计原样保留，于是花括号直接显示在界面上。

- **减少动态效果把加载指示器冻成了静态**：`prefers-reduced-motion` 的规则用裸
  `*` 选择器把 `animation-iteration-count` 一律压成 1，连圆形加载指示器和
  不确定进度条一起打中 —— `linear infinite` 被砍成一帧就定格在起始角度。
  对正在等请求的用户来说，不转的转圈更像卡死。表达「正在进行」的动画改为
  用 `.motion-essential` 豁免，装饰性的渐入/上滑/呼吸仍然照常收掉。

## v1.0.9-beta — 2026-08-10

### 新增

- **起飞/降落派生指标接上真实计算**（G）：抬轮速度、抬轮到离地耗时、
  35ft 俯仰角、起飞稳定性、进近稳定性、剩余跑道 —— 这六项此前**恒为 `--`**。
  查下来既不是 bug 也不是移植遗漏：数据模型、序列化、i18n、渲染四样都齐了，
  但**从来没有代码往里写过值**，Flutter 桌面版同样只有标签没有计算。
  现在在录制收尾时统一算出来（这些量要看事件前后一整段，采样时算不了）：
  - **抬轮点**从离地点往回找，遇到「回到空中」就停 —— 训练起落航线里
    接地续滑全程保持抬头，俯仰判据根本不会触发，只有这条能把上一段航程隔开，
    否则会一路回溯并报出上一次起飞的抬轮速度；
  - **35ft 俯仰角**优先用无线电高度，机型不提供时退回「气压高度 - 离地时高度」——
    刚离地几十秒里气压没时间漂，硬要无线电高度等于一大批机型永远拿不到这项；
  - **剩余跑道**按坐标反查跑道几何后沿中线投影，再按机头朝向决定往哪头算 ——
    方向搞反会把「还剩 400 m」报成「还剩 2600 m」，而这个数正是用来判断能不能停住的。
  - **两个稳定性评分的公式是本项目自拟的**（桌面版没有可对齐的实现），
    只用于横向比较自己的几次飞行，不对应任何行业标准；判据取自通行的
    稳定进近准则（下降率/坡度/速度稳定性），但扣分权重是本项目定的，
    全部集中在 `takeoff-landing-metrics.ts` 顶部的常量里，要调直接改。

- **指标取不到时显示原因而不是 `--`**：区分「本机型不提供离地高度」「未采到抬轮过程」
  「采样点不足」「未能定位所在跑道」「本次未记录到起飞/落地」五种情况。
  统一一个 `--` 等于什么都没说 —— 用户无从判断是自己没飞到、还是程序坏了。

- **地图飞行罗盘图层**（B）：开关与 store 早就通了，缺的是图层本身。
  按桌面版 `compass_ring.dart` 移植：每 5° 一格的刻度环、N/E/S/W 方位字母、
  航向线与自动驾驶目标航向箭头，中心徽标优先显示目标航向（有目标时
  飞行员关心的是「要转到哪」）。底图切到卫星这类亮图时整体换高对比配色。

- **点击本机显示航空器信息面板**（E）：移植桌面版 `aircraft_info_mini_panel.dart`。
  面板可拖、对视口做 clamp（拖出界就再也找不回来了），引线接点随面板在飞机
  哪一侧切换 —— 接错侧会让引线横穿面板把数字盖住。显示航班号/注册号、高度、
  地速、应答机编码与状态。

- **机场详情卡片可收起**（I）：原先只有关闭按钮，一关就丢掉整个选中状态。
  收起后只留 ICAO / 机场名 / 等级徽标 / 跑道条数，以及「本机在哪条跑道上」。
  收起是**真的不渲染**详情而不是压高度：这张卡是纵向 flex，
  用 max-height 压会把子项沿纵向挤扁，页签压到 10px 而行高 16.5px，字被裁掉一半。

- **本机所在跑道高亮**（J）：跑道列表里把本机正压着的那条标出来。
  判据是「点到线段垂距 < 半宽」且「投影落在线段内」两条同时成立 ——
  只算端点距离会漏掉跑道中段，只算垂距会把延长线上几公里外的飞机也算进来。
  另加离地高度门槛，否则从跑道正上方三千英尺飞过也会被判成「在跑道上」。

- **EFB 单页飞行卡**（新模块 `modules/efb`）：一屏放下当前飞行阶段、该阶段的
  关键门限、近场机场与气象、油量余度。门限按阶段给（进近看下降率/坡度/构型，
  滑行看地速与停留刹车…），逼近上限就转黄，不等超了才报红。
  **数据缺失显示「—」并判为 unknown，绝不当成通过** —— 把「没有数据」画成
  「一切正常」是这类面板最危险的失败方式。
  油量余度算的是「落地时还剩多少、够不够最低储备」，而不是油箱里还有多少 ——
  后者是个大数字，看着永远很安心。

- **检查单模板与自动切换**：新增「下载空白模板」，模板本身就是合法的导入文件，
  预置了各阶段空节段与示例，填完直接导回。
  导入格式扩充为版本号 / 机型注册码（可多个）/ 适用模拟器（可多选），
  txt/csv 走注释头（`# registration: B-6075`），老解析器会原样跳过。
  连上模拟器后按**注册码 → 模拟器 → 机型名 → 家族**的优先级自动切换：
  注册码只对应一架飞机，用户为它专门写的检查单不该被泛化的机型模板盖掉；
  同一注册码有多份时，显式点名当前模拟器的那份赢过「不限」的那份。

- **训练模式 / 复盘模式切换**（顶栏常驻）：复盘模式下暂停一切实时联动 ——
  检查单不再跟遥测走、EFB 不再自动拉气象、地图不再跟随飞机。
  这些自动化在飞行中是帮忙，落地复盘时全是干扰：你正对着一段慢慢翻，
  阶段却被刷回冷舱、地图每 500ms 把你拽回实时机位。模式持久化。

- **跨模块任务流**（顶栏常驻）：把 Briefing → Map → Checklist → Flight Logs
  串成一条有顺序的线，显示「已完成/总数」，点任一步直接跳转。
  每步都从已有状态自动判定完成，同时允许手动跳过 —— 有人就是不用简报直接飞，
  卡着不让走只会让人弃用这个功能。

### 调整

- **飞行日志三个子模块改为嵌入父容器**（D）：轨迹地图 / 飞行质量报告 /
  黑匣子明细原先各自套一层 `SectionCard`，卡片边框加父容器 padding
  两头夹掉近 60px 宽度，地图和宽表格首当其冲。这三块各自独占一个页签，
  外面再包一层「窗口」没有分组意义，改为贴边铺满。

- **WebSocket 改用增量帧**：连接时带 `?delta=1`，中间件只推变更字段，
  本地由 `WsDeltaAssembler` 合并还原。`base_seq` 对不上说明丢帧，
  这时**要一帧全量而不是硬合并** —— 硬合并出来的状态不会报错，
  只会让某几个字段永远停在旧值上。中间件不支持增量时照常收全量，无需改动。

- 机型注册码（`aircraft_atc_id` / tailnum）纳入飞行数据模型，供检查单匹配使用。

### 删除

### 修复

  实测两种写法差 0.06 ppm（4200 海里差 0.00025 海里），远低于导航数据本身的精度。

### 删除

- **清理无人引用的导出**（14 处）：`calculateBearingDeg`（与 `bearingDeg` 重复实现）、
  `pickArray`、`contrastRatio`、`isGroupElement`、`LocalizationKey`、`PENDING_SYNC_KEY`、
  `airportDisplayName`、`termDisplayValue`、`MapDataSnapshot`、`MapRunwayApproach`、
  `ConfigurableAlertId`、`resolveApproachRule`、`normalizeApproachRule`、
  `APPROACH_RULE_COLOR`。
- **`flightDataSelectors` 及其 4 个便捷 hook**：移植期照搬桌面版 `FlightDataProvider`
  的 getter 代理，但全部 29 处订阅点都用的内联选择器，这套从未被采用。

### 修复

- **界面显示的版本号永远是写死的回退值**：`app-constants.ts` 写的是
  `import.meta.env.VITE_APP_VERSION ?? '1.0.3-beta'`，而这个环境变量
  **从来没有人注入过** —— vite.config、CI、npm scripts 里都没有。于是侧边栏
  显示的一直是那个回退值，1.0.4 都要发了还挂着 1.0.3。
  现由 vite.config 从 package.json 构建期注入，并把该回退值纳入
  `check-version-sync` 的校验范围（此前它只看 package.json/CHANGELOG/README）。
- **航迹每帧整条重建**（违反 `DESIGN.md` NFR-3「增量更新，不整层重建」）：
  去掉点数上限后这个问题会直接把 UI 拖死，因此一并改为**分段渲染**。
  注意「只 `addLatLng` 新点」并不够 —— Leaflet 的 `addLatLng` 内部会
  `redraw()` 把整条线重新投影，实测 6000 点时单帧开销仍从 0.08ms 涨到 0.93ms。
  改为每 500 点冻结一段、只有末段在长之后，单帧开销与航迹总长基本无关：
  6000 点 0.93ms → 0.042ms；50000 点（≈4 小时航程）也只有 0.114ms。
- **一个抛异常的 store 订阅者会让它后面的订阅者全部收不到通知**：选中机场时
  `map.flyTo(..., Math.max(map.getZoom(), 15))` —— 上一次飞行动画还没结束就再次
  选中，`getZoom()` 返回 NaN，`Math.max(NaN, 15)` 仍是 NaN，Leaflet 抛
  "Invalid LatLng object"。而这是 Zustand 的订阅回调，异常会中断 `Set.forEach`，
  排在后面的订阅者（各面板的 React 订阅）全部收不到通知 —— 表现为「地图动了，
  但机场底卡不出来」，控制台只有一条看起来无关的 Leaflet 报错。已给缩放级别兜底。
- **地图图层有 6 处外部文本未转义就进了 innerHTML**（NFR-6）：Leaflet 的
  `divIcon` 与 `bindTooltip` 传字符串时内部都是 `node.innerHTML = content`，
  所以这两处都是 XSS 落点。文本来源并不都可信 —— 滑行道要素的 `ref`/`name`
  来自 **OpenStreetMap**（任何人可编辑），自绘滑行道的 `segment.name` 可由用户
  **从 JSON 文件导入**（别人分享的文件同样能带脚本）。同一个 `airport.code`
  在一个渲染器里转义、另一个里没转义，正是这类不一致的典型。
  6 处已全部走 `escapeHtml`，该函数移到 `core/utils/escape-html.ts` 并补 6 例单测
  （含「`&` 必须最先替换」这条容易改错的顺序约束），另补上了单引号转义。
- **`String(x ?? '')` 会把类型不对的字段伪装成合法字符串**：后端字段是 `unknown`，
  真传来对象时 `String()` 得到 `"[object Object]"` —— 非空，于是调用方随后的
  `.trim().length === 0` 判空永远不成立，脏数据一路流进界面。全项目 45 处已改用
  `toText()`（非标量一律当作没有值）；`toStringOrUndefined` 同样的洞一并修掉。
- **两处本地重复实现的 `asText`** 收敛到公共实现（`flight-log-models` 与
  `middleware-flight-data-adapter` 各写了一份）。
- **日志丢栈信息**：`AppLogger.error` 的 `stackTrace` 走 `String()`，传对象时整条栈
  变成 `"[object Object]"`，等于什么都没记；改走已有的 `stringifyError`。
- **非 JSON 请求体被发成 `"[object Object]"`**：`serializeBody` 在 content-type
  不是 JSON 时对对象直接 `String()`；改为 `JSON.stringify`，至少可读可排查。
- **气象解码把时间戳当成能见度**（用户可见）：`extractWorstVisibility` 的正则少了
  两侧 `\b`，于是时间戳 `052300Z`、风组 `01004MPS`、跑道视程 `R36L/1200N`、
  修正海压 `Q1024` 里的四位数字全被当成能见度候选 —— 而该函数取的是**最小值**。
  结果是任何一份报文都会被风组数字判成 LIFR，连 `CAVOK`（能见度与云幕俱佳）
  都会显示成 LIFR。同文件的 `decodeMetar` 一直用的是带 `\b` 的正确写法，
  是这个 helper 抄漏了。
- **架构门禁漏判副作用导入**：`scripts/check-architecture.mjs` 原先只匹配
  `from 'x'`，`import 'leaflet';` 这类副作用导入完全看不见 —— 铁律形同虚设。
  改为统一用 `importPattern()` 生成正则，同时覆盖 `from` / 裸 `import` / `require`。
