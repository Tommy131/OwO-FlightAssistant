## P2 · 中期

### 4. SimBrief OFP 导入 ✅

**问题**：`showPlannedRoute` 开关在 store 里、i18n 有「计划航程」词条，
但**没有任何数据源** —— 整个航路功能是空壳。简报的燃油至今是
`距离 × 2.5` 的粗估（见 `buildFuelPlanTotal`）。

**为什么选 SimBrief 而不是自己解算**：一次 API 调用即可拿到完整航路 +
真实燃油/配载 + SID/STAR 建议，同时喂饱「航路显示」与「简报数据」两块；
自解算需要先解析 `earth_awy.dat`（航路库，后端目前一个字节都没碰），
工作量大一个量级。

**已做**：后端代理接口（归一化，210KB → 5KB）、简报页导入并回填表单、
地图计划航路图层（SID/STAR 与巡航分色）、右侧控制栏开关。

**一个纠正**：原以为要 API key，实测**读取已有 OFP 不需要** —— 那个 key 是给
「生成航路」用的。只要用户名或数字 Pilot ID，两者都不是密钥，按普通设置项存即可。

**燃油也已接入**：导入后简报逐项用 OFP 真实配载，单位沿用 OFP 自己的；
没导入则退回粗估，正文标明来源。

## P3 · 差异化，工作量较大

### 6. ~~地面滑行引导~~（已完成）

**已经有的**：aeroway 矢量（滑行道中心线**带 ref 编号**）、停机位坐标与朝向、
一个完整的自绘滑行道编辑器（命名 / 限速 / 撤销重做 / 导入导出）。

**要做的**：把滑行道连成图（带权无向图），支持
①按管制指令高亮路线（"A5, B, hold short 36L"）；②从廊桥自动规划到跑道口，
给出滑行距离与预计时间。

**✅ 已完成（2026-08-09）**：`taxi-graph.ts`（58 例单测 + RCNN 真实机场夹具）
提供建图、最短路（跑道段带惩罚权重）、管制指令解析、按指令依次沿指定滑行道规划、
按编号分段、滑行时间估算；界面上有指令输入面板、机位/跑道快捷起终点与高亮图层。
EDDM 实测：指令 `via E1, S, B2, hold short 08R` → 4.35 km / 约 10 min。

**⚠️ 原先对难点的判断是错的。** 这里原本写着「图论部分不难，难点在 OSM 数据的
连通性清洗（断头、重复节点、缺失连接）」—— 实测完全不是这样：OSM 在每个路口就把
滑行道切成独立的 way，相邻 way 共享节点，Overpass 吐出的坐标逐位相同。
EDDM 3509 个节点按坐标原样建图，99% 落在同一连通分量（RCNN、EDDN 是 100%）。
反倒要**避免**按距离吸附 —— 间距十几米的平行滑行道会被粘成一条。

真正的难点是「沿着走」而不是「碰到」：走到某条道的端点不等于沿它滑过；
管制只念关键道、中间连接段不念但确实要走；同一个编号在 OSM 里可能是几截
互不相连的道。这三条各返工了一次，全靠真实数据才暴露出来。

时间模型也返工过一次：第一版按「单步航向变化超过 30 度算转弯」，在 OSM 上一个弯
都识别不出来（弯被拆成十来个顶点，每步只转十几度），算出的时间与纯直线只差 1%。
改成按累计转角计费后，EDDM 四条真实路线折合均速 13.1–13.6 kt。

**遗留**：滑行时间对采样密度仍有残余敏感（同一个弯拆成 45 段以上会归零），
彻底消除要改成按固定距离窗口比较航向。当前数据源下够用，已在代码注释里写明。
