## P0 · 进行中

### 1. 移除航迹点上限 + 航迹增量渲染

**问题**：`MAX_ROUTE_POINTS = 4000` 配合 300ms 轮询，巡航时采样点间隔约 69m，
**4000 点只够约 20 分钟**，长航线必然丢失前半程航迹。

**已经有的**：`MapRoutePoint` 已存经纬度 / 高度 / 地速 / 时间戳；
`MIN_ROUTE_POINT_DISTANCE_M = 30` 的距离过滤天然抑制了静止时的刷点。

**要做的**：
- [x] 去掉 `MAX_ROUTE_POINTS` 上限
- [x] 航迹改为**增量渲染** —— 原实现每次遥测都 `remove()` 再整条重建 polyline，
      去掉上限后长航线会把 UI 拖死。这同时是补上 `DESIGN.md` NFR-3
      「高频遥测下地图图层增量更新，不整层重建」的欠账。

## P1 · 近期（数据已在手，只差呈现）

### 2. 落地回放

**已经有的**：`state.route` 里每个点都带 `timestamp` / `altitude` / `groundSpeed`，
去掉上限后是一条完整的时间序列；飞行日志已按点存 G 值与告警。

**要做的**：时间轴拖动条 —— 拖动时把飞机标记移到对应时刻的点，
同步显示该时刻的高度/速度/垂速。数据零新增，纯前端。

### 3. 落地评分卡

**已经有的**：`resolveSnapshotPointG()` 已在算接地 G（取各起落架最大值，
带有效区间过滤，机体 G 兜底），并已入库到飞行日志。

**要做的**（数据大多已在 `FlightData` 里）：
- 接地垂速（FPM）—— `verticalSpeed`，取接地瞬间
- 距跑道入口距离 —— 接地点 `landingPoint` 与跑道几何算
- 中线偏移 —— 同上
- 侧风分量 —— METAR 风向风速 × 跑道朝向

评分卡本身是既有功能的扩展，不是新模块。

## P2 · 中期

### 4. SimBrief OFP 导入

**问题**：`showPlannedRoute` 开关在 store 里、i18n 有「计划航程」词条，
但**没有任何数据源** —— 整个航路功能是空壳。简报的燃油至今是
`距离 × 2.5` 的粗估（见 `buildFuelPlanTotal`）。

**为什么选 SimBrief 而不是自己解算**：一次 API 调用即可拿到完整航路 +
真实燃油/配载 + SID/STAR 建议，同时喂饱「航路显示」与「简报数据」两块；
自解算需要先解析 `earth_awy.dat`（航路库，后端目前一个字节都没碰），
工作量大一个量级。

**要做的**：
- 后端加 SimBrief 代理接口（API key 走环境变量，**不入库**）
- 前端简报模块加「从 SimBrief 导入」，填充起降/备降/航路/燃油
- 地图 `plannedRoute` 接上真实数据

### 5. SID/STAR/进近程序完整绘制

**已经有的**：`approach.go` 已在读 CIFP，但只匹配 `APPCH:` 行、
且只取程序标识首字母判断进近类型 —— **SID 与 STAR 一行都没读**。
进近波束与等待航线的绘制管线已经跑通。

**要做的**：解析程序航段（航路点序列 + 高度/速度限制），在地图上画出完整程序。
`DESIGN.md` 记着的 FAS 数据块（可用于精确绘制 LPV/GLS 保护区）同属这一项。

## P3 · 差异化，工作量较大

### 6. 地面滑行引导

**已经有的**：aeroway 矢量（滑行道中心线**带 ref 编号**）、停机位坐标与朝向、
一个完整的自绘滑行道编辑器（命名 / 限速 / 撤销重做 / 导入导出）。

**要做的**：把滑行道连成图（带权无向图），支持
①按管制指令高亮路线（"A5, B, hold short 36L"）；②从廊桥自动规划到跑道口，
给出滑行距离与预计时间。

图论部分不难，难点在 OSM 数据的连通性清洗（断头、重复节点、缺失连接）。

### 7. 航路气象剖面

依赖 #4。Open-Meteo 已接入，有了航路即可沿航线画高空风/温度剖面。
