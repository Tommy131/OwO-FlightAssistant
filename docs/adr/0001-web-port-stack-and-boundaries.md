# ADR 0001 — Web 移植的技术栈与前后端边界

- 状态：已采纳
- 日期：2026-08-04

## 背景

Flutter 桌面版 OwO! FlightAssistant 需要一个浏览器版本。桌面版是模块化微内核架构，
业务逻辑与 UI 已经分离，配套的 Go 中间件（OwO-FlightAssistant-Middleware）承担
模拟器对接、导航数据解析与外部服务代理。中间件**暂不开源**。

需要决定：用什么栈重写前端、桌面专属能力如何取舍、前后端如何划界与分发。

## 决策

### 1. 栈：React 19 + TypeScript + Vite + Zustand，不引 UI 组件库

Zustand 的 store 订阅模型与 Flutter `provider` / `ChangeNotifier` 一一对应，
移植时状态层结构可以逐个平移。不引 MUI —— 桌面版的设计语言要逐像素复刻，
第三方主题体系反而会打架，改成手写组件 + CSS 变量注入。

### 2. 桌面能力：合理降级，不套 Tauri/Electron

保留全部业务功能，只放弃浏览器没有对应能力的两项：无边框标题栏、
首启向导里的「选择本地存储路径」。文件导入导出改用 `<input type=file>` + Blob，
通知用 Notification API。代价是无法访问任意本地路径，但业务上不需要。

### 3. CORS：开发期 Vite 代理，生产期同源托管

不为了跨域去改中间件。开发期 `/mw-api` → `127.0.0.1:18080`、`/mw-ws` → `18081`；
生产期由中间件直接托管前端构建产物，天然同源。

### 4. 前后端边界与分发

- 前端仓库（本仓库）**公开**，源码 + CI 全在 GitHub。
- 中间件仓库**私有**，只以编译产物形式随本仓库的 Release 分发。
- 前端源码物理上放在中间件工作区的 `web/` 子目录（便于本地一体化开发与托管），
  但 **`web/` 是独立 git 仓库**，中间件仓库的 `.gitignore` 排除它。
  两个仓库物理嵌套、git 上完全隔离 —— 闭源后端源码不可能被推到公开仓库。

## 后果

**正面**

- 用户只需下载 Release 里的中间件可执行文件，启动后直接访问前端页面，无需装 Node。
- 前端可独立开源、独立走 CI 与 PR 流程，不牵扯闭源后端。
- 状态层与桌面版同构，两端可以对照维护。

**负面 / 需要留意**

- 目录物理嵌套容易让人误以为是同一个仓库。任何在中间件仓库执行 `git add -A` 的人
  都应确认 `.gitignore` 里的 `web/` 仍在 —— 这一条写进了 CLAUDE.md 的变更影响矩阵。
- 前端发版依赖中间件同步发版（托管产物路径约定为 `web/dist`）。
- 浏览器无法访问任意本地路径，日志/简报的「另存到指定目录」只能走下载。
